## 一、为什么要开发 ParrotClaw

我经历了互联网、移动互联网、人工智能三个时代。

这一路走过来，最深的感受是：**人工智能正在改变所有软件的交互方式。** 从以前需要学习复杂操作的图形界面，到未来用自然语言直接对话就能完成工作的 AI 问答模式——这不是渐进式的改进，而是一次彻底的范式转变。

100 年后的世界会是什么样子？人类的生产力将会大解放，也许就像《机器人总动员》里那样，充满无限的想象。

我希望在当今这个时代，我们都能留下点什么有价值的东西。

ParrotClaw，就是我想留下的那个东西。

## 二、ParrotClaw 开发历程

Parrot 项目最早可以追溯到 2023 年。

**2023 — parrot_app**

第一批版本通过本地配置直连大模型 API，实现了基础的 AI 对话功能。那时候想法很简单：把 AI 装进 App 里，让对话变得触手可及。

**2025 — parrot_desktop**

桌面端版本，引入了 Spring AI 作为后端，具备了更完整的多轮对话和工具调用能力。但这个架构还是太重了，维护成本和灵活性都不太理想。

**2026 年 — OpenClaw 出现**

这一年 OpenClaw 强势发布。作者看到了 OpenClaw 的 Agent 编排能力——内置的 Skills、Plugins、语音交互、工具链集成……这完全就是一直想要的那个后端。

与其自己从零搭架构，不如把精力放在前端体验上。**基于 OpenClaw 打造一个真正的 AI 数字员工 App**，这个想法自然而然地出现了。

于是，ParrotClaw 诞生了。

### 与官方 OpenClaw App 的区别

OpenClaw 官方 App 功能强大，但对国内用户有几个门槛：

- **Google 服务依赖** — 国内大部分手机没有 Google Services，离线语音识别无法使用
- **交互方式偏技术** — 更适合开发者使用

ParrotClaw 针对这些痛点做了改进：

| 特性 | 官方 OpenClaw App | ParrotClaw |
|------|------------------|------------|
| 语音识别 | 依赖 Google 在线服务 | 基于 sherpa-onnx 的离线识别，支持中文，不依赖 Google，不联网 |
| 数字人 | 无 | 集成 Live2D，增加数字人朗读交互趣味 |
| 消息格式 | 仅文本 | **图片展示、音视频文件播放**，富媒体消息原生支持 |
| 多服务器配置 | 仅支持单服务器连接 | **多服务器管理**，一个 App 同时连接多台 OpenClaw 或工具链服务器，灵活切换 |
| 跨平台 | 仅移动端 | **Flutter 跨平台**，一套代码覆盖移动端与桌面端，一致体验 |

简单来说：**ParrotClaw 让 AI 数字员工在国内环境下也能跑起来，而且更好玩。**

除了针对国内环境的本土化改进之外，ParrotClaw 在工程架构上也有独特的亮点：

**多服务器配置** — 不同于官方 App 只能连接一台后端服务器，ParrotClaw 支持同时配置和管理多个服务器连接。你可以把生产环境和测试环境分开，也可以将不同功能的 Agent 部署在不同服务器上统一管理。对于有 ComfyUI 生图工作站、TTS 服务器、OpenClaw 编排中心的用户来说，一个 App 搞定所有后端切换。

**跨平台 Flutter 架构** — 基于 Flutter 构建，一套代码同时覆盖 Android、iOS、Windows、macOS、Linux。用户数据跟随账号，在不同设备间无缝衔接。对开发者而言，维护成本大幅降低，新功能一次开发全平台生效。
